# Engineering Documentation Clarifier

重写中英文技术文档，提高可读性并清除 AI 协作痕迹，同时不改变技术含义。

指令本体见 [SKILL.md](SKILL.md)。

## 适用

- README、架构 / 设计文档、协议说明
- API / CLI 文档、Roadmap、Changelog、安装指南、故障排查、工程笔记
- 清除仓库文档中的 AI 汇报腔、请示回执、排比免责句与机械契约表格（去 AI 痕迹）
- 按 ASD-STE100 风格原则改写英文工程文档

不适用：创意写作、营销文案、日常对话、代码重构，以及需要改设计本身而不是改文档的请求。

## 规则要点

- 不新增事实、结论、假设或实现细节
- 保留真实限制与不确定性（合并为简洁的已知限制 / TODO，不在每段末尾反复叠甲）；`must / should / may / can` 的差别原样保留
- 清除 AI 请示与交差语句（如“按用户要求…”、“获授权运行…”、“没有使用付费 API”、“仅做静态检查未跑测试”等）与内部证据标签
- 去除“X 不等于 Y / 不代表 Z”排比免责腔、机械对称的“负责 / 不负责”表格以及工整的四字总结前缀
- 命令、API、标识符、状态名、错误名、协议术语、路径、数字、版本、代码不动
- 改写后不在文档中追加任何“本次仅改文档、未重跑测试”等免责说明；全仓整理时提示排查 `AGENTS.md` / `.ai/` 等 AI 脚手架文件

英文参考 ASD-STE100 的部分原则，不要求严格 STE 合规：句子直接、主语和条件明确、该用主动语态就用、常用词、拆开过密的长句、去掉空泛和营销式表达。

中文用对应的工程写法：句子紧凑，条件、动作、结果写明确，多用直接动词，少长定语和嵌套的“的”，去掉不必要的“进行 / 实现 / 相关 / 对应 / 相应”，技术术语保持原样。

## 使用

把本目录放进你的 agent 的 skills 目录。当你要求重写、精简、去 AI 痕迹或提高某份技术文档的可读性时，agent 会自动选用它。
